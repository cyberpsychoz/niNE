# Шаблон плагина для niNE

Этот шаблон содержит базовую структуру плагина для быстрого старта разработки.

## Быстрый старт

### 1. Скопируйте шаблон

```bash
# Из корня проекта
cp -r plugin_template plugins/my_plugin
cd plugins/my_plugin
```

### 2. Настройте метаданные

Откройте `sh_plugin.py` и измените:

```python
PLUGIN_INFO = PluginInfo(
    unique_id="author.my_plugin",        # ← Ваш уникальный ID
    name="My Plugin",                    # ← Название плагина
    description="Описание плагина",      # ← Описание
    author="YourName",                   # ← Ваше имя
    version="1.0.0",
    dependencies=[],                     # ← Добавьте зависимости если нужно
    load_order=60,
    enabled=True,
)
```

### 3. Выберите нужные модули

**Если нужен только серверный модуль:**
- Оставьте `sv_logic.py`
- Удалите `cl_ui.py`

**Если нужен только клиентский модуль:**
- Оставьте `cl_ui.py`
- Удалите `sv_logic.py`

**Если нужны оба:**
- Оставьте оба файла

**Если не нужна конфигурация:**
- Удалите `sh_config.py`

### 4. Настройте модули

Измените названия классов и логику в файлах:

**sv_logic.py:**
```python
class MyServerModule(PluginModule):  # ← Переименуйте класс
    # ... ваша логика ...
```

**cl_ui.py:**
```python
class MyUIModule(PluginModule):  # ← Переименуйте класс
    # ... ваша логика ...
```

### 5. Тестирование

Запустите сервер и клиент:

```bash
python server.py
python client.py
```

Проверьте логи на наличие сообщений о загрузке плагина.

## Структура шаблона

```
plugin_template/
│
├── sh_plugin.py       # Метаданные плагина (ОБЯЗАТЕЛЬНО)
│   └── PLUGIN_INFO - информация о плагине
│   └── on_plugin_load() - хук загрузки
│
├── sv_logic.py        # Серверный модуль (опционально)
│   └── ServerModule - класс серверной логики
│
├── cl_ui.py           # Клиентский UI модуль (опционально)
│   └── UIModule - класс клиентского UI
│
└── sh_config.py       # Общая конфигурация (опционально)
    └── Константы и настройки
```

## Что есть в шаблоне

### sh_plugin.py
- ✅ Полная структура PLUGIN_INFO с комментариями
- ✅ Хук on_plugin_load() с примером использования
- ✅ Инициализация shared_data
- ✅ Условная логика для сервера/клиента

### sv_logic.py
- ✅ Базовая структура серверного модуля
- ✅ Обработчики player_joined и player_left
- ✅ Примеры хранения данных игроков
- ✅ Отправка сообщений в чат
- ✅ Полное документирование кода

### cl_ui.py
- ✅ Создание UI с DirectGUI
- ✅ Обработка game_state_changed
- ✅ Примеры DirectFrame, DirectLabel, DirectButton
- ✅ Методы показа/скрытия UI
- ✅ Загрузка текстур и звуков
- ✅ Полное документирование кода

### sh_config.py
- ✅ Примеры констант всех типов
- ✅ Настройки UI, игры, сервера
- ✅ Цвета, сообщения, пути к ресурсам
- ✅ Организованная структура

## Примеры использования

### Минимальный плагин (только метаданные)

```
plugins/minimal/
    sh_plugin.py
```

### Серверный плагин (логика на сервере)

```
plugins/server_plugin/
    sh_plugin.py

```

### Полноценный плагин (сервер + клиент)

```

    sh_plugin.py
    sv_logic.py
    cl_ui.py
    sh_config.py
```

## Советы

### Именование

- **Файлы:** `sv_*` для сервера, `cl_*` для клиента, `sh_*` для общих
- **Классы:** `MyPluginServerModule`, `MyPluginUIModule`
- **События:** `author.plugin_name.event_name`

### Организация кода

- Один класс PluginModule на файл
- Группируйте методы по функциональности
- Добавляйте docstrings ко всем методам
- Используйте type hints

### Производительность

- Не используйте app_tick без необходимости
- Кешируйте данные где возможно
- Очищайте ресурсы в on_unload()
- Избегайте тяжелых операций в обработчиках событий

### Отладка

- Используйте self.logger для логирования
- Проверяйте наличие данных в словарях (dict.get())
- Добавляйте try-except для критических операций
- Тестируйте перезагрузку плагина
