# Концепция "Живого Мира" для niNE
## Inspiration: Kenshi + RimWorld для мультиплеера в мире D&D

---

## 🎯 ГЛАВНАЯ ИДЕЯ

**Создать онлайн мультиплеерный мир D&D, где каждый NPC "живёт своей жизнью" с уникальными статами, потребностями, отношениями и памятью — как в Kenshi и RimWorld, но с возможностью играть вместе с друзьями.**

### Что это значит?

- **300+ NPCs** с индивидуальным поведением живут в мире одновременно
- **Каждый NPC уникален**: имя, характер, потребности, история, отношения
- **Мир эволюционирует**: NPCs взаимодействуют друг с другом, создают союзы, конфликты, романы
- **Эмерджентный геймплей**: интересные истории возникают сами из взаимодействия систем
- **Наблюдение как геймплей**: можно просто смотреть как живёт мир, не вмешиваясь
- **Последствия имеют значение**: убить торговца = город теряет снабжение, помочь кузнецу = лучшие цены

### Почему это круто?

В отличие от "статичных" MMO, где NPCs стоят на месте и говорят одни и те же фразы:
- NPCs **спят, едят, работают, общаются** по своим расписаниям
- NPCs **помнят** что вы сделали и **меняют отношение** к вам
- NPCs могут **подружиться** с игроками, **предать**, **влюбиться**, **мстить**
- Если убить главу гильдии — его заменят, гильдия может **объявить войну** вашей фракции
- Город может **процветать** или **разрушиться** в зависимости от действий игроков

## 🧠 ТЕКУЩЕЕ СОСТОЯНИЕ NPC AI

### Что работает СЕЙЧАС (февраль 2026):

#### ✅ Базовая AI (плагин `npc/`):
```python
AIBehavior:
- IDLE        — стоит на месте
- WANDER      — случайное блуждание в радиусе
- PATROL      — патрулирование по точкам
- NEUTRAL     — не атакует первым, защищается если провоцировать
- HOSTILE     — агрессивен, атакует игроков в aggro_radius
- FOLLOW      — следует за целью
```

**Поведение в бою:**
- Детекция врагов в `aggro_radius` (5-10 метров)
- Pursuit (преследование) с учётом `leash_radius` (30 метров)
- Attacking в `attack_range` (2 метра)
- Переходы IDLE → PURSUING → ATTACKING → IDLE
- Интеграция с боевой системой (инициатива, ходы)

**Оптимизация (300+ NPCs):**
- **AI LOD System** — далёкие NPCs думают реже (0.5s → 5s интервалы)
- **Spatial Hash** — O(k) поиск ближайших врагов вместо O(n)
- **Delta Compression** — синхронизация только изменений
- **Interest Manager** — клиенты получают только ближайших NPCs

#### ✅ Living World (плагин `living_npc/`):
```python
NeedsComponent:
- hunger: 100.0 → 0.0 (decay 0.5/час)
- energy: 100.0 → 0.0 (падает при активности)
- social: 100.0 → 0.0 (падает в одиночестве)
- safety: 100.0 → 0.0 (падает при угрозах)
- comfort: 100.0 → 0.0 (зависит от окружения)
- purpose: 100.0 → 0.0 (падает при бездействии)
```

**Черты характера (18+ traits):**
- Социальные: EXTROVERT, INTROVERT, CHARISMATIC
- Рабочие: HARD_WORKER, LAZY, PERFECTIONIST
- Боевые: BRAVE, COWARD, BLOODTHIRSTY, PACIFIST
- Моральные: KIND, CRUEL, HONEST, DECEITFUL
- Особые: NIGHT_OWL, EARLY_BIRD, GLUTTON, ASCETIC

**Отношения:**
- opinion: -100 до +100 (как сильно нравится)
- trust: 0 до 100 (доверие)
- familiarity: 0 до 100 (насколько знакомы)
- relationship_type: acquaintance, friend, rival, lover, enemy, family

**Память:**
- События сохраняются с timestamp, importance, description
- Decay со временем (важные помнятся дольше)
- Влияют на будущие решения

**Расписания:**
- Активности по часам: sleep, work, eat, socialize, patrol
- Priorities определяют выбор при конфликте
- Chance of deviation (20%) для спонтанности

## 🚀 ROADMAP: От "Smart" к "Alive"

### Этап 1: Реакция на потребности (CRITICAL) ⏳

**Цель:** NPCs активно удовлетворяют потребности

**Реализация:**
```python
# В AISystem.update() перед выбором поведения:
def _choose_action_based_on_needs(self, npc):
    needs = npc.get_component(NeedsComponent)
    personality = npc.get_component(PersonalityComponent)

    # Приоритизация по критичности
    if needs.hunger < NeedsComponent.CRITICAL:
        if personality.has_trait(TraitType.HONEST):
            return AIBehavior.SEEK_FOOD  # Ищет еду легально
        else:
            return AIBehavior.STEAL_FOOD  # Ворует еду

    if needs.safety < NeedsComponent.CRITICAL:
        return AIBehavior.FLEE  # Бежит в безопасное место

    if needs.energy < NeedsComponent.LOW:
        return AIBehavior.SEEK_REST  # Ищет кровать

    # Если всё в порядке — обычное поведение
    return npc.ai.behavior
```

**Результат:**
- NPCs ищут еду когда голодны
- NPCs спят когда устали
- NPCs ищут компанию когда одиноко
- NPCs убегают из опасных мест

### Этап 2: Влияние черт на AI (HIGH) ⏳

**Цель:** Черты реально меняют поведение

**Примеры:**
```python
if personality.has_trait(TraitType.BRAVE):
    ai.aggro_radius *= 1.5  # Более агрессивен
    ai.leash_radius *= 2.0  # Преследует дальше

if personality.has_trait(TraitType.COWARD):
    # Бежит раньше (при 50% HP вместо 20%)
    if combat.hp_current < combat.hp_max * 0.5:
        ai.behavior = AIBehavior.FLEE

if personality.has_trait(TraitType.LAZY):
    ai.work_efficiency *= 0.75  # Работает медленнее
    needs.energy_decay *= 0.5   # Но меньше устаёт

if personality.has_trait(TraitType.KIND):
    # Помогает раненым союзникам
    if nearby_ally.combat.hp_current < nearby_ally.combat.hp_max * 0.3:
        cast_spell("Cure Wounds", target=nearby_ally)
```

**Результат:**
- Brave NPCs дерутся до смерти
- Coward NPCs бегут рано
- Kind NPCs лечат раненых
- Cruel NPCs добивают врагов

### Этап 3: Социальные взаимодействия (HIGH) ⏳

**Цель:** NPCs общаются друг с другом

**Реализация:**
```python
# Новое поведение: SOCIALIZE
class SocializeSystem(System):
    def update(self, dt, entities):
        for npc in entities:
            needs = npc.get_component(NeedsComponent)
            relationships = npc.get_component(RelationshipsComponent)

            if needs.social < NeedsComponent.LOW:
                # Ищет друга поблизости
                friend = self._find_nearby_friend(npc, relationships)
                if friend:
                    self._interact(npc, friend)
                    needs.social += 10.0  # Восстанавливает social

                    # Формирует воспоминание
                    memory.add_memory(
                        event_type="pleasant_chat",
                        with_entity=friend.id,
                        importance=5,
                        description=f"Приятно поговорили с {friend.name}"
                    )
```

**События взаимодействий:**
- "helped_in_fight" → opinion +15, trust +10
- "shared_food" → opinion +5, trust +5
- "insulted" → opinion -10, trust -5
- "saved_life" → opinion +50, trust +40
- "betrayed" → opinion -80, trust -90

**Результат:**
- NPCs болтают когда скучно
- Формируются дружбы
- Возникают конфликты
- Память о событиях влияет на будущее

## 💡 ФИЛОСОФИЯ: Эмерджентность

### Что делает мир "живым"?

**НЕ скриптовые события**, а **простые системы взаимодействующие друг с другом:**

**Пример 1: Голодный торговец**
```
1. Merchant работает 8-18, продаёт еду
2. Hunger падает, достигает CRITICAL
3. Merchant закрывает магазин → ищет еду
4. Находит Farmer → покупает еду → hunger восстанавливается
5. Возвращается в магазин → открывает снова

НО если Farmer мёртв:
1. Merchant не находит еду
2. Hunger достигает 0 → умирает
3. Город теряет торговца → игроки не могут купить еду
4. Другой NPC может занять место merchant (если есть profession система)
```

**Пример 2: Любовный треугольник**
```
1. NPC_A (CHARISMATIC) флиртует с NPC_B
2. NPC_B (EXTROVERT) отвечает взаимностью → opinion +20
3. Relationship становится "romantic_interest"
4. NPC_C (тоже любит NPC_B) видит это → opinion к NPC_A падает (-30)
5. NPC_C (CRUEL trait) решает убить NPC_A
6. Игрок может:
   - Не вмешиваться → NPC_A умирает → NPC_B мстит NPC_C
   - Спасти NPC_A → NPC_A становится другом игрока
   - Помочь NPC_C → NPC_B становится врагом игрока
```

**Пример 3: Война за ресурсы**
```
1. Drought event → еды мало
2. Alliance и Horde оба нуждаются в ресурсах
3. Alliance атакует Neutral city (где есть еда)
4. Horde видит слабость → атакует Alliance
5. Игроки могут:
   - Помочь Alliance → защитить city → +rep Alliance
   - Помочь Horde → ослабить Alliance → +rep Horde
   - Защищать Neutral → остаться нейтральным → +rep Neutral
6. Исход влияет на карту: кто контролирует city
```

### Ключевые принципы:

1. **Causality** — каждое действие имеет последствия
2. **Autonomy** — NPCs принимают решения сами
3. **Memory** — прошлое влияет на будущее
4. **Emergence** — сложность из простых правил
5. **Player Agency** — игроки влияют, но не контролируют всё
